# Напарник · Локальный шлюз

Программа для подключения 1С:Напарника к ZCode, DeepSeek Harness и другим текстовым ИИ-клиентам. Локальный сервер и панель в браузере используют один порт на 127.0.0.1. Генерацию выполняет сервис 1С.

## Настольное приложение

Скачайте установщик для своего компьютера со [страницы релизов Ingvar Consulting](https://github.com/IngvarConsulting/naparnik-relay/releases/latest). Пакет включает сервер и использует системный WebView для панели. Node.js отдельно устанавливать не требуется.

| Система | Установка |
| --- | --- |
| macOS 14+, Apple Silicon или Intel | Выберите DMG для своего процессора и перетащите Naparnik Relay в «Программы». |
| Windows 10/11 x64 | Запустите установщик EXE для текущего пользователя. Интерфейс использует Microsoft Edge WebView2. |
| Linux x86_64 | Скачайте AppImage, разрешите выполнение в свойствах файла и запустите его. Пакет собирается на Ubuntu 22.04. |

Первая версия для macOS распространяется без нотариализации Apple. Если система заблокировала открытие приложения, попробуйте открыть его один раз, затем в «Системные настройки → Конфиденциальность и безопасность» найдите сообщение о Naparnik Relay и выберите «Всё равно открыть». Windows может показать SmartScreen для нового издателя.

**Обновление.** В меню Naparnik Relay выберите «Проверить обновления…». Программа проверяет релиз в GitHub, предлагает установить новую версию, проверяет цифровую подпись пакета и перезапускается. Для Linux храните AppImage в доступной для записи папке. Закрытие окна оставляет шлюз работать. Через значок Naparnik Relay в системном трее (на Mac — в строке меню) можно открыть окно, проверить обновления или завершить приложение. Завершение приложения останавливает его шлюз.

**Переход с браузерной версии.** Остановите прежний сервер командой `npm stop` из каталога проекта и откройте приложение. Адрес, локальный ключ и сохранённый ключ Напарника читаются из прежнего каталога. Ключ, который хранился только в памяти, потребуется ввести снова.

## Запуск из исходников

Нужен Node.js 22 или новее. В macOS откройте «Запустить Напарник.command». Из терминала выполните `npm start`. Программа запускает шлюз в фоне и открывает панель в системном браузере. Повторный запуск открывает тот же шлюз. Для остановки выполните `npm stop`. Для запуска сервера в терминале есть команда `npm run serve`.

Нажмите **Подключить аккаунт** и вставьте API-ключ из раздела «Ключи доступа» кабинета Напарника. Панель проверяет ключ запросом бюджета, показывает расход за пять часов и неделю, а также время обновления каждого лимита, когда оно известно. Открытая панель периодически обновляет данные. Журнал показывает время, длительность и результат последних 12 запросов текущего подключения.

По умолчанию ключ Напарника хранится в памяти процесса. Флажок «Запомнить ключ» сохраняет его в локальном файле `~/.naparnik-relay/connection.json` в открытом виде с правами 0600. Отключение аккаунта удаляет сохранённый ключ Напарника. Тот же файл содержит отдельный ключ для клиентов и секрет для открытия панели. Для переноса каталога или смены порта задайте `RELAY_DATA_DIR` или `RELAY_PORT` и при запуске, и при остановке.

## Настройка клиентов

Скопируйте **локальный API key** из панели. Оба профиля используют модель `naparnik`. Это локальное имя движка 1С.

| Клиент | Протокол | Base URL по умолчанию |
| --- | --- | --- |
| ZCode | OpenAI Chat Completions | `http://127.0.0.1:47831/v1` |
| DeepSeek Harness | Anthropic Messages | `http://127.0.0.1:47831` |

**ZCode.** Откройте Model settings → Add provider → Create custom provider. Введите Base URL, выберите Chat Completions и вставьте локальный ключ. Добавьте модель по ID, включите её и нажмите Test model.

**DeepSeek Harness.** В Settings → Models откройте карточку DeepSeek. Вставьте локальный ключ в API key и адрес в Customized settings → Base URL. Нажмите Add model, задайте ID `naparnik` и название «1С:Напарник». Нажмите Apply и выберите эту модель в сессии. Изменение Base URL встроенного провайдера применяется ко всем его моделям. Чтобы сохранить отдельное подключение к DeepSeek, в версиях с поддержкой пользовательских провайдеров можно создать свой профиль с протоколом Anthropic Messages.

## Совместимость

Шлюз обслуживает `GET /v1/models`, `POST /v1/chat/completions` и `POST /v1/messages`. Он принимает Bearer или x-api-key, обрабатывает обычные и SSE-ответы, текстовые сообщения, схемы функций и результаты их выполнения. Клиент сам выполняет инструменты. Шлюз переводит имена инструментов в отдельное пространство имён Напарника.

Напарник хранит диалоги на сервере и принимает роли user и tool. Шлюз связывает повторно переданную клиентом историю с серверным диалогом и сообщением-родителем. Он хранит в памяти до 1024 таких соответствий. Системные инструкции и присланная история без известного соответствия передаются текстом в новом диалоге. Учтите разницу в приоритете системных инструкций при этой трансляции.

SSE передаёт подтверждённые сообщения ассистента, как только они завершены. Напарник может исправить предварительные дельты. Шлюз отдаёт окончательный текст и аргументы. Вложения и OpenAI Responses API не поддерживаются. Настройки температуры, ограничения длины вывода и режимов рассуждения не применяются движком через публичный API. Поля usage в формате Anthropic — оценка по длине текста, квоты в панели приходят из 1С.

Проверка протоколов с локальным имитатором — `npm test`. Она охватывает авторизацию, повторные сообщения с результатами инструментов, финализацию и ошибки потока.

[Публичный API 1С:Напарника](https://code.1c.ai/public-api/) · [Настройка ZCode](https://zcode.z.ai/en/docs/configuration) · [Настройка DeepSeek Harness](https://deepseek-harness.github.io/deepseek-harness/en/guide/providers)


## Сборка релиза

Нужны Node.js 24, Rust stable и [системные зависимости Tauri](https://v2.tauri.app/start/prerequisites/). Выполните `npm ci`, затем `npm run desktop:build -- --bundles app,dmg` на Mac, `--bundles nsis` на Windows или `--bundles appimage` на Linux. Скрипт проверяет SHA-256 дистрибутива Node.js перед упаковкой. Для выпуска обновлений используется закрытый ключ `TAURI_SIGNING_PRIVATE_KEY`. Открытый ключ включён в приложение.

Публикацию запускает владелец репозитория через Actions → Desktop release → Run workflow на ветке main. Версия берётся из package.json. После сборки четырёх пакетов workflow формирует latest.json и SHA256SUMS и публикует релиз. Идентификатор приложения и открытый ключ обновлений должны сохраняться между версиями.
