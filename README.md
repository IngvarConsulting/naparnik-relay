# Напарник · Локальный шлюз

Программа для подключения 1С:Напарника к ZCode, DeepSeek Harness и другим текстовым ИИ-клиентам. Локальный сервер и панель в браузере используют один порт на 127.0.0.1. Генерацию выполняет сервис 1С.

## Настольное приложение

Скачайте установщик для своего компьютера со [страницы релизов Ingvar Consulting](https://github.com/IngvarConsulting/naparnik-relay/releases/latest). Пакет включает сервер и использует системный WebView для панели. Node.js отдельно устанавливать не требуется.

| Система | Установка |
| --- | --- |
| macOS 14+, Apple Silicon или Intel | Выберите DMG для своего процессора и перетащите Naparnik Relay в «Программы». |
| Windows 10/11 x64 | Запустите установщик EXE для текущего пользователя. Интерфейс использует Microsoft Edge WebView2. |
| Linux x86_64 | Скачайте AppImage, разрешите выполнение в свойствах файла и запустите его. Пакет собирается на Ubuntu 22.04. |

Первая версия для macOS распространяется без нотариализации Apple. Если система заблокировала открытие приложения, попробуйте открыть его один раз, затем в «Системные настройки → Конфиденциальность и безопасность» найдите сообщение о Naparnik Relay и выберите «Всё равно открыть». Windows может показать SmartScreen для нового издателя.

**Обновление.** В меню значка Naparnik Relay в системном трее (на Mac — в строке меню) выберите «Проверить обновления…». Программа проверяет релиз в GitHub, предлагает установить новую версию, проверяет цифровую подпись пакета и перезапускается. Для Linux храните AppImage в доступной для записи папке. Закрытие главного окна оставляет шлюз работать. Через меню значка можно вновь открыть окно или завершить приложение.

**Переход с браузерной версии.** Остановите прежний сервер командой `npm stop` из каталога проекта и откройте приложение. При стандартном адресе и каталоге настольное приложение использует тот же профиль. Ключ, который хранился только в памяти, потребуется ввести снова. Настольный шлюз завершается через меню значка в трее.

Для переноса нестандартного подключения остановите браузерный сервер с теми же `RELAY_PORT` и `RELAY_DATA_DIR`, с которыми он запущен. Перенесите `connection.json`, каталог `sessions/` и, при наличии, `tools.json` из браузерного профиля в `~/.naparnik-relay/desktop/`. Если там уже есть профиль, сохраните его копию перед заменой. Запишите прежний номер порта в файл `~/.naparnik-relay/desktop/port`, затем откройте приложение.

## Запуск из исходников

Нужен Node.js 22 или новее. В macOS откройте «Запустить Напарник.command». Из терминала выполните `npm start`. Программа запускает шлюз в фоне и открывает панель в системном браузере. Повторный запуск открывает тот же шлюз. Для остановки выполните `npm stop`. Для запуска сервера в терминале есть команда `npm run serve`.

Нажмите **Подключить аккаунт** и вставьте API-ключ из раздела «Ключи доступа» кабинета Напарника. Панель проверяет ключ запросом бюджета, показывает расход за пять часов и неделю, а также время обновления каждого лимита, когда оно известно. Открытая панель периодически обновляет данные. Запросы и ответы доступны по сессиям в окне «Трассировка».

При первом подключении включён флажок «Запомнить на этом компьютере». Снимите его, чтобы хранить ключ только до завершения приложения. При включённом флажке шлюз сохраняет ключ в локальном файле `~/.naparnik-relay/connection.json` в открытом виде с правами 0600. Отключение аккаунта удаляет сохранённый ключ Напарника. Тот же файл содержит отдельный ключ для клиентов и секрет для открытия панели. Для переноса каталога или смены порта задайте `RELAY_DATA_DIR` или `RELAY_PORT` и при запуске, и при остановке.

Адрес настольного шлюза постоянен. По умолчанию он использует порт 47831. Для существующего подключения на другом порту настольное приложение поддерживает профиль в `~/.naparnik-relay/desktop/`: файл `port` содержит номер порта, а `connection.json` хранит настройки и ключ этого подключения. Приложение использует этот профиль при обычном запуске и после обновления. Если порт занят, оно сообщает об этом.

## Разработка

```sh
npm run dev
```

Шлюз работает в текущем терминале. Node.js сохраняет вывод и перезапускает сервер при изменении его JavaScript-модулей. Остановить процесс можно через Ctrl+C. Для этой команды достаточно Node.js 22 или новее.

Когда в терминале появится адрес шлюза, откройте панель командой `npm start` во втором терминале. Она подключится к работающему серверу. После перезапуска снова выполните `npm start`, чтобы восстановить вход в панель. Изменения HTML, CSS и браузерного JavaScript видны после обновления страницы.

## Настройка клиентов

Скопируйте **локальный API key** из панели. Оба профиля используют модель `naparnik`. Это локальное имя движка 1С.

| Клиент | Протокол | Base URL по умолчанию |
| --- | --- | --- |
| [ZCode](docs/clients.md#zcode) | OpenAI Chat Completions | `http://127.0.0.1:47831/v1` |
| [DeepSeek Harness](docs/clients.md#deepseek-harness) | Anthropic Messages | `http://127.0.0.1:47831` |

[Инструкция по подключению клиентов](docs/clients.md) включает проверку новой сессии и настройку веб-инструментов DeepSeek Harness.

## Настройки и трассировка

«Настройки» открывает окно с параметрами новых диалогов и разрешениями для инструментов Напарника. Начальные значения языка интерфейса, языка программирования и языка комментариев — `ru / 1c / ru`. Relay сохраняет выбранные языки при изменении и использует их при создании диалога, в том числе после перезапуска.

По умолчанию разрешены все серверные инструменты, кроме чтения веб-страниц. Разрешения сохраняются между перезапусками. Шлюз передаёт Напарнику `accepted` или `rejected` для вызовов, запрашивающих разрешение. Новые серверные инструменты появляются в списке при первом вызове.

«Трассировка» открывает отдельное окно со списком сессий. В обеих колонках HTTP-запрос и его ответ раскрываются одной карточкой с кодом ответа рядом со временем запроса. Стрелки идут от исходного пакета к связанному, а нажатие на номер открывает его карточку. Для серверных инструментов пунктир связывает запрос агента с вызовом Напарника, а сплошная стрелка ведёт от вызова к подтверждению релея. В колонке агента вызов клиентского инструмента связан с запросом, которым агент вернул результат. Тела подсвечиваются как JSON и SSE. Подтверждение сохранения сообщения связано с запросом, а пустое начало сообщения ассистента и финал с тем же UUID доступны в одной карточке. Дельта, открывшая клиентский SSE-поток, получает метку «Старт потока». Остальные черновики отмечаются `SKIP Draft`, а терминатор `[DONE]` — `DONE`. Прокрутка колонок связана по пакетам, её можно разъединить переключателем. Журнал хранит недавние данные в памяти, маскирует ключи и очищается при перезапуске шлюза или смене аккаунта.

## Совместимость

Шлюз обслуживает `GET /v1/models`, `GET /v1/models/naparnik`, `POST /v1/chat/completions` и `POST /v1/messages`. Он принимает Bearer или x-api-key, обрабатывает обычные и SSE-ответы, текстовые сообщения, схемы функций и результаты их выполнения. Клиент выполняет свои инструменты и управляет их разрешениями. Шлюз переводит имена клиентских инструментов в отдельное пространство имён Напарника.

Напарник хранит диалоги на сервере и принимает роли user и tool. Relay сопоставляет историю `messages` с сохранённым ответом и отправляет только новые сообщения и результаты инструментов. При отсутствии совпадения или при неоднозначной истории Relay создаёт отдельный диалог. Для подключения достаточно стандартного OpenAI Chat Completions или Anthropic Messages, Base URL, локального ключа и модели `naparnik`.

Необязательный `x-session-id` группирует запросы одной сессии. Интеграции, которые отправляют только новые сообщения без предыдущих ответов, могут явно указать `X-Relay-Input: delta` вместе с `x-session-id`. Relay также поддерживает ID и типы запросов, которые некоторые клиенты отправляют штатно. Если запрос DeepSeek Harness на название содержит ID чата, Relay вызывает `/title` этого диалога. При `424` он может дождаться следующего ответа и повторить запрос в пределах 55 секунд.

После завершённого ответа Relay сохраняет привязку в подкаталоге `sessions/` локального профиля. Для запроса с ID хранится до 128 контрольных точек на сеанс, а для запросов без ID — до 1024 контрольных точек на аккаунт. Каждая содержит хеш истории, ссылку на ветку Напарника и данные о вызовах инструментов. При перезапуске Relay продолжает ветку по сохранённой истории. Текст переписки и API-ключ в файлы привязок не записываются. Привязки для передачи результатов по ранее выданным ID инструментов действуют в пределах текущего процесса и аккаунта.

Для SSE достаточно параметра `stream: true`. Шлюз открывает поток при первой дельте 1С. Когда 1С завершает очередное сообщение, Relay отправляет его текст одной дельтой OpenAI или Anthropic. Аргументы каждого клиентского инструмента передаются целиком. Напарник может исправить предварительные дельты, поэтому содержимое берётся из финального пакета. Вложения и OpenAI Responses API не поддерживаются. Настройки температуры, ограничения длины вывода и режимов рассуждения не применяются движком через публичный API. Relay передаёт usage последней генерации Напарника. В OpenAI-потоке для этого нужен stream_options.include_usage. Поле naparnik_context содержит token_count и max_context_length из измерения ветки в 1С. Предварительный /v1/messages/count_tokens требует токенизатора для произвольного входа, которого публичный API 1С не предоставляет. В настройках модели ZCode и DeepSeek Harness укажите contextWindow из этого ответа. При отсутствии статистики генерации Relay опускает OpenAI usage и заполняет обязательные числовые поля Anthropic нулями.

Для привязанных сеансов и продолжений с распознанной историей Relay сохраняет идентификатор диалога и отпечаток операции перед отправкой сообщения, затем сохраняет подтверждения по мере получения. После обрыва SSE или перезапуска Relay сверяется с `GET /public/v1/conversations/{uuid}`. Если 1С сохранила ответ в нужной ветке, Relay возвращает его и сохраняет восстановленный `parent_uuid`. Если в истории виден принятый запрос, а ответ ещё недоступен, Relay сообщает `recovery_pending`. Повторная отправка возможна для того же запроса, когда история доступна и подтверждения сохранения запроса нет.

### Нативная компактизация 1С

1С автоматически сжимает контекст при приближении к лимиту. Для явного сжатия возьмите UUID из заголовка ответа Relay `X-Relay-Conversation-Id` и отправьте `POST /v1/conversations/{uuid}/compact` с обычным локальным API-ключом. Тело можно опустить или передать объект с необязательной строкой `instruction`. Relay выполняет сжатие на стороне 1С и возвращает `compact_finished` или `compact_limited`. Публичный метод 1С возвращает статус операции, сохраняя сжатый контекст на стороне сервиса. Чтобы продолжить тот же диалог после сжатия, используйте один и тот же `x-session-id` с первого запроса генерации.

Chat Completions не определяет отдельный вызов компактизации. Запросы резюмирования через обычный `messages` остаются обычными текстовыми запросами. Компактизация Anthropic beta и OpenAI Responses требует другого формата результата, который этот маршрут не эмулирует.

### Удаление диалога из агента

Клиент может отправить `DELETE /v1/conversations/{uuid}` с локальным ключом Relay в `Authorization: Bearer …` или `x-api-key`. UUID берётся из заголовка `X-Relay-Conversation-Id` ответа на генерацию. Relay удаляет диалог через API Напарника и очищает локальные ссылки на этот UUID после подтверждения. Ответ Relay содержит `id`, `object: "conversation.deleted"` и `deleted: true`. Если по диалогу выполняется запрос, Relay возвращает `409` и клиент может повторить удаление после его завершения.

Клиент должен отправить этот запрос явно. Удаление локального чата в ZCode и архивация сессии в DeepSeek Harness проходят на стороне клиента и не вызывают этот маршрут.

Проверка протоколов с локальным имитатором — `npm test`. Она охватывает авторизацию, повторные сообщения с результатами инструментов, финализацию и ошибки потока.

## Сборка релиза

Нужны Node.js 24, Rust stable и [системные зависимости Tauri](https://v2.tauri.app/start/prerequisites/). Выполните `npm ci`, затем `npm run desktop:build -- --bundles app,dmg` на Mac, `--bundles nsis` на Windows или `--bundles appimage` на Linux. Скрипт проверяет SHA-256 дистрибутива Node.js перед упаковкой. Для выпуска обновлений используется закрытый ключ `TAURI_SIGNING_PRIVATE_KEY`. Открытый ключ включён в приложение.

Публикацию запускает владелец репозитория через Actions → Desktop release → Run workflow на ветке main. Версия берётся из package.json. После сборки четырёх пакетов workflow формирует latest.json и SHA256SUMS и публикует релиз. Идентификатор приложения и открытый ключ обновлений должны сохраняться между версиями.
